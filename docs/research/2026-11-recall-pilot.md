# 群友怎么回忆：标注试点与回忆策略层 v0（2026-11-11）

属于记忆的第三个想法（让记忆像人），接 `2026-11-humanlike-memory-directions.md` 的路线 A 和路线 B。
本文只有汇总数字和代号，没有聊天内容。只用了两个 DEV 群；VALIDATION 群和 FROZEN 群没有碰。

## 1. 结论

1. **群友的回忆大多不是在回忆群聊。**模型标出的回忆语句里，回忆群内聊天的只占 14% 到 20%，其余主要是群外经历。能当作「人怎么回忆群聊」样本的，两个群合计只有 126 条。
2. **形式上几乎不引原话。**全部回忆里引原话的占 2% 到 3%，说大意约六成，只提到有这回事约三成。约两成带不确定的措辞，约一成是没人问、话题也没到就自己提起的。这和行为目标 S1、S3、S5 的方向一致。
3. **「回忆对上哪条原文」这一步现在不可信。**同一批 42 条回忆让两个模型各判一次，有 24 条至少被一个模型对上了原文，其中两个模型指向同一行的只有 4 条。时间间隔、角色、忠实度这些从对应关系推出来的数字只能当线索，等人工核对。
4. **引用回复不能当回忆样本。**两个群共 10,792 条引用回复，中位间隔半分钟，99% 在 4.5 小时内，引用一天以前消息的总共 6 条。引用是对话手段，不是回忆。
5. **回忆策略层 v0 能跑，但规则表是暂定的。**它不调模型，只按「谁说的、多久以前、是不是玩笑梗、后来有没有再被提起」决定每段证据给原话、大意、只说有这回事，还是不给。空跑结果：交给回答模型的记忆文本从约 1,280 字降到 210 到 540 字。还没有生成回答，也没有做盲评。
6. **卡在两处**：DeepSeek 账户余额用完（接口返回 402），后面的回答生成跑不了；一、二阶段的标签要等用户抽查。

## 2. 路线 B：做法

| 步骤 | 做什么 | 代码 |
| --- | --- | --- |
| 粗筛 | 正则找带回忆标记的消息（记得、忘了、来着、上次、谁说的、好像有印象等六类） | `bench/recall/markers.py` |
| 一阶段 | 模型看目标消息的前 12 条和后 6 条，判断是不是回忆，并标对象、行为、形式、把握、起因、之后的反应 | `bench/recall/run_label.py` |
| 二阶段 | 只对「回忆群内聊天」的条目：用冻结的检索 V2 取 8 段候选原文，逐行编号，模型指出回忆的是哪一行，或者说都不是 | `bench/recall/run_link.py` |
| 引用间隔 | 不用模型，直接统计引用回复和被引用消息的时间差 | `bench/recall/report.py` |
| 人工核对 | 抽样做成离线标注页，带原名，放在仓库外 | `bench/recall/label_pack.py`、`bench/labelkit/pages/recall_round1.js` |

几点说明：

- 检索只能看到回忆那一刻之前的消息，而且排除了模型已经看到的上下文。
- 写得像程序的账号（消息里大量 Markdown、平均很长）整体剔除。DEV-1 没有，DEV-2 有一个，去掉了 70 条候选。
- 粗筛的正则比方向文档第 8 节的探查版宽，所以候选数比那里的多（247 对 153，764 对 498）。
- 二阶段第一版让模型抄一句原话再去匹配，结果把话题相近的段落也算成对上了，已作废；现在的版本是编号行加「宁缺毋滥」的要求。

## 6. 路线 A：回忆策略层 v0

代码在 `bench/recall/policy.py`，空跑脚本是 `bench/recall/run_policy.py`。

位置在检索和回答模型之间。检索照旧，存储不动，什么都不删。策略层只决定每段证据以什么粒度交给回答模型：

| 档位 | 给回答模型的内容 | 来源 |
| --- | --- | --- |
| 原话 | 原文 | 原文块 |
| 大意 | 一句摘要 | 上色时已有的摘要，不再调模型 |
| 有这回事 | 只有话题和大致时间 | 摘要截短 |
| 不出现 | 不给 | — |

暂定的规则表（行是机器人在这段对话里的角色，列是距今多久）：

| | 一天内 | 一周内 | 一个月内 | 更早 |
| --- | --- | --- | --- | --- |
| 自己说过 | 原话 | 原话 | 大意 | 大意 |
| 对自己说的 | 原话 | 大意 | 大意 | 有这回事 |
| 在场 | 大意 | 大意 | 有这回事 | 有这回事 |
| 不在场（入群前） | 不出现 | 不出现 | 不出现 | 不出现 |

另外三条：

- 标成玩笑梗的段落，或者一小时以后又被人引用回复过的段落，清楚一档。
- 「有这回事」一次最多给 2 条。
- 用户明说要查记录、要原话时走精确模式，全部给原文。

**这张表里的格子和阈值都是我定的初值，没有数据依据。**方向来自文献（S2 角色差别、S3 默认只留大意），具体到哪一格没有拟合过。等路线 B 的标签核对完再调。

空跑结果（问题在数据末尾提出，取排名前 12 段，预算 1,500 字，没有调用回答模型）：

| | DEV-1 旁观者 | DEV-1 以最活跃成员的视角 | DEV-2 旁观者 |
| --- | --- | --- | --- |
| 问题数 | 441 | 441 | 436 |
| 给出的档位：原话 / 大意 / 有这回事 | 65 / 698 / 882 | 277 / 1,633 / 847 | 9 / 670 / 872 |
| 平均记忆文本字数：策略层 / 冻结版 | 257 / 1,283 | 538 / 1,283 | 213 / 1,249 |
| 冻结版给了原文的标准证据，现在变成：原话 / 大意 / 有这回事 / 不出现 | 0 / 33 / 336 / 26 | 14 / 106 / 179 / 96 | 0 / 29 / 255 / 32 |

怎么读这张表：

- 问题都放在数据末尾提出，标准证据多数已经是一周以前的，所以旁观者视角下它们绝大多数落到「有这回事」（DEV-1 是 395 条里的 336 条）。按这张表，机器人会对多数旧事说「有印象但记不清」。
- 「有这回事」每次最多 2 条，排名靠后的旧段落因此直接不出现，这是记忆文本变短的主要原因。这是不是像人、是不是太过，要靠盲评判断，不能用问答准确率判断。
- 换成参与者视角，原话和大意明显变多，说明角色这一维确实在起作用。
- 精确模式下全部回到原文，和冻结版一致。
