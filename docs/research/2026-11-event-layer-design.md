# 事件层设计与最小原型（2026-11-06）

> 状态：研究原型，**旁路**。事件层只读取冻结版 B 的块和原始消息，不参与 B/RRF 的召回、排序、截断、预算或回填。以后要融合，必须用显式开关单独消融（任务书阶段 4）。

## 1. 为什么要单独一层

冻结版检索擅长「某件事的原文在哪」：小块、少噪声、能精确定位原文（证据进入率 89.8% / 72.5%）。但有一类问题它从结构上答不了：

| 问题 | 需要什么 | 块级检索为什么不行 |
|---|---|---|
| 最乱的那个晚上 | 整段时间的属性：并行话题、打断、刷屏 | 属性分布在很多块的先后关系里，单块看不出；问题里也没有词面线索 |
| 最热闹 / 最后一次那么热闹 | 跨晚上比较 | top-k 片段不是完整的比较依据 |
| 某个梗第一次被全群玩起来 | 时间聚合 + 「全群」的扩散 | 需要按时间扫证据，不是按相似度取前几 |
| 两个人关系变化最明显的几次 | 长时期、多事件的证据 | 同上，且需要比较 |

离线三方案实验已经说明，把局部块合成大块会显著降低证据进入率（merged-v1：−5.9 / −7.3）。所以不把块变大，而是**在块之上另建一层，只存引用**。

## 2. 层次和数据结构

```text
原始消息（不变）
  └ B 局部颜色块（冻结，注入单元）            blocks.B.jsonl：block_id、msg_ids、indexed_msg_ids、时间、scope
      └ 事件层（旁路，可重建，带版本）
          ├ episode   一段连续的聊天（基线：两次沉默之间）
          │   └ thread  episode 内同一语境延续的几个块（子事件）；一个 episode 可以有多个并行 thread
          ├ link      不同日期的 episode 之间的关系（话题重提、续接），只存关系，不合并
          └ impression 对事件的解释（后续研究）
```

事件记录（`bench/events/build.to_json`）：

| 字段 | 内容 |
|---|---|
| `event_id`、`scope` | `group:<代号>`；作用域隔离，事件只引用同一个群的块 |
| `intervals` | 一个或多个时间段（中断后隔天继续的事件有多段） |
| `source_refs` | `{block_id, n_in_episode, first_msg, last_msg}`；不复制原文 |
| `subevents` | thread：`block_ids`、时间、消息数 |
| `features` | 只含结构特征（见第 3 节），不含任何对心理状态的断言 |
| `impressions` | v0 为空；格式见第 4 节 |
| `version` | `events-v0` |

一个 B 块的消息可能落在两个 episode 里（块跨越了一次沉默），所以引用记的是这个 episode 里的消息范围，不是整块。

## 3. v0：不调用模型的基线

- **episode**：按沉默切分，默认 30 分钟，至少 20 条。
- **thread**：相邻批次在重叠区上出了同一段语境的两个颜色，连成一个 thread（沿用 merged-v1 的匹配规则，但**只作为链接**，不改检索块）。可选：摘要向量余弦 ≥ τ 且时间相接的块也连起来（v1，τ 待标注后再定）。
- **结构特征**（`features`）：消息数、时长、每分钟消息数及峰值、发言人数、发言均匀度（归一化熵）、换人率、回复占比、图片占比、@ 占比、thread 数、**thread 交错率**（按时间顺序，相邻两条消息属于不同 thread 的比例）、每 10 分钟并行 thread 数的均值和最大值。
- 「乱」不简化成消息条数。交错率和并行 thread 数是结构上更接近「几件事同时在聊、互相打断」的量；它们和人工打分的关系要在标注回来后检验，不预设。

首次构建（沉默 30 分钟）：

| | DEV-1 | DEV-2 |
|---|---:|---:|
| episode（≥20 条） | 93 | 87 |
| 覆盖消息 | 92% | 98.7% |
| 每个 episode 消息数（中位 / 最大） | 71 / 2,193 | 94 / 5,588 |
| thread 数（中位 / 最大） | 3 / 69 | 5 / 197 |
| 已上色的消息 | 69% | 64% |

**已发现的问题**：

1. 热闹的日子整天不停，沉默切分会切出几千条的「事件」。单靠沉默不够，需要再按话题或时段细分；这正是要和人工标注比较的地方。
2. 约三分之一的消息没有上色（上色失败的批次、太短的消息），这些消息不属于任何 thread。
3. 容器时区是 UTC，群聊是北京时间。事件层统一按 UTC+8；此前打标页的「活跃日期」按 UTC 显示，可能差一天。

## 4. 印象（后续研究的格式约定）

印象是**主体的解释**，不是事实，必须和原始记录分开存放，并带来源：

```yaml
impression_id: I17
event_id: <event>
kind: initial | reinterpretation | correction | retraction
text: 多个话题交错、频繁打断
basis: structural_features | model_reading | human_label | later_event
evidence_refs: [<block_id / msg range>]        # 必填，指回原文
derived_from: [<impression_id>]                  # 改写自哪条印象
formed_at: <回放时间点>                          # 只能用这个时间点之前的信息
trigger: <引发重新解释的事件或消息>            # reinterpretation 必填
confidence: null | 低 | 中 | 高
```

- 原始记录不可被印象覆盖；重新解释是追加新版本，旧版本保留。
- **防止自我强化**：独立性只按 `evidence_refs` 里不同的原始消息计数；Agent 自己复述、回忆或模型生成的摘要不算新证据（`derived_from` 链上的都算同源）。
- 区分四种状态，不要合成一个「遗忘分数」：证据是否存在（原文永久保留）；痕迹强弱（研究概念）；当前线索下能否被找到（检索可及性）；现在怎么理解（解释）。时间只是可及性的一个因素，不决定删除。

## 5. 评测

第一套专项题围绕「晚上」：北京时间 18:00 到次日 6:00，消息不少于 100 条。DEV-1 有 23 个晚上，DEV-2 有 20 个。

**人工标注（第一轮，打标页已发给用户）**：

1. 先不看记录，凭印象写最难忘、最乱、最热闹、最尴尬的晚上，用来检验「印象先行」的假说：人想起的是不是结构上最突出的那几晚。
2. 逐晚打分：有没有印象（本来记得 / 看了想起来 / 没印象）、乱（1–5）、热闹（1–5）、标签（冲突、刷屏、集体玩梗、尴尬、重要消息、来去、求助、图片、深夜长谈）、一句话。
3. 从全部晚上里挑「最乱、最热闹、最尴尬、最难忘」。

页面**不显示**任何结构特征，避免标注被要检验的量带偏。

**要比较的方案**（同一批题）：

| 方案 | 做法 | 成本 |
|---|---|---|
| R0 冻结版检索 | 把问题直接交给 B/RRF，取回 1500 字原文，让模型回答是哪一晚 | 每题 1 次回答 |
| E0 结构特征排序 | 按某个特征排晚上，不调用模型 | 0 |
| E1 事件卡片比较 | 每晚一张卡（时间、thread 摘要、结构特征），模型在全部卡片里比较后选出，再回到 B 块核对原文 | 每题 1 次，输入较长 |
| E2 带印象的卡片 | E1 加上每晚的模型印象（需先为每晚生成一次） | 每晚 1 次 + 每题 1 次 |

指标：选中的晚上是否在人工挑出的那一晚 / 人工评分前 3；与人工评分的 Spearman 相关；回答引用的原文是否真在那一晚；token 和耗时。E0 用到的特征只在标注回来后才看它与人工的关系，**不用标注调特征之后再在同一批数据上报告**：两个群互为验证。

## 7. 预先存档的预测（2026-11-06，标注交回之前）

`bench/events/run_evening_qa.py` 对三个问题（最乱、最热闹、最尴尬的晚上）跑了 R0、E0、E1，结果写在各运行目录的 `events.evening_qa.predictions.json`（带生成时间）。**这些预测在人工标注交回之前生成，之后不改**；标注回来后只做评分。

- 回答模型调用 12 次（每群 R0、E1 各 3 次），E1 每次输入约 1.4 万 token（全部卡片），R0 约 1,300 token。
- R0 在 6 题里有 3 题回答「不知道」，另有 1 题选中的晚上不足 100 条、不在候选里。检索回来的片段分散在多个日子，且有一部分是白天的。块级检索确实很难回答这类问题，但对不对要等标注。
- E1 在 DEV-1 选的「最乱」和 E0 的交错率、并行话题数第一名是同一晚；DEV-2 选的是消息最多的那一晚。E1 可能只是在读卡片上的统计数字，评分时要和 E0 单个特征比较，看模型有没有提供特征以外的信息。

## 8. 调整（2026-11-07，读文献后）

- 印象层的首要用途改为**检索线索**（定位事件），回答一律回到 B 块和原文构建；印象不进入任何「证据」计数。
- 不实现时间衰减或遗忘；可及性由线索决定，作为检索排序问题研究。
- 事件专项评测新增「含糊指代还原」（如「上次那事」指哪一段），优先级高于「最……」类问题。详见 `2026-11-cognitive-memory-notes.md` 第 10 节。
