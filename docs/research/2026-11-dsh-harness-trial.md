# 用 dsh 代替 AstrBot 做 bot 运行框架：试跑记录（2026-11-11）

起因：用户考虑抛掉 AstrBot，改用 dsh 或 Pi（两者都是通用的代码 agent 框架，适配量估计相近）；本机只有 dsh，先用它试；将来上 Windows 也要 Linux 沙箱。

本文接在 `2026-11-workspace-notes.md` 之后，那篇是围绕 AstrBot 写的，没有改动。

范围：读了本机安装的 `@deepseek-ai/dsh` 0.2.1-rc.4 的随附文档，并用**合成群聊**实际跑了 6 次。没有接 QQ，没有用真实聊天，没有动用户正在运行的 dsh 网页服务。Pi 没有试。

## 1. 结论

1. **能用，而且接入量小。** dsh 有一个专门给外部程序驱动的入口（`dsh --profile sdk-minimal`，标准输入输出上的 JSON-RPC）。我用一个约 60 行的驱动脚本加一个假的「发群消息 / 查聊天记录」工具服务，第一次就跑通了：不接话、查记录后回答、用 shell 算数并写文件，三种情况都对。
2. **文章里工作区的三件事，dsh 都有现成的**：shell、脚本式工具调用、子会话。前两件实跑过，子会话只读了文档。
3. **dsh 自带的沙箱不够当「专属工作区」用。** 实测它挡住了写工作区以外的文件，也不把密钥环境变量带进 shell；但**读不设限**（shell 里能列出 `~/.dsh` 的内容）、**网络不设限**（能访问本机其他服务）。文档自己也写明它只约束文件操作。
4. **所以 Linux 沙箱要在 dsh 外面套**：把整个 dsh 进程放进容器（Windows 上经 WSL2），容器里不放 QQ 凭据和真实聊天库，发消息和查记录由容器外的进程转手。这正好是文章的结构，也让 Windows 和 Linux 用同一套部署。
5. **要自己写的部分**：QQ 接入（OneBot 反向 WS）、攒批和是否接话、发送、聊天记录库。AstrBot 原本替我们做了第一项和一部分第二项。

## 2. 试跑

位置：`qqbot-data/runs/dsh-trial-2026-11-11/`（脚本、补丁、事件日志；全部是合成内容）。模型走本机模型网关 的 `gemini-3.8-flash-high`，共 24 次模型调用，输入 56,011、输出 1,326 token，已记入台账。

组合方式：`sdk-minimal` 档 + 一个补丁文件，补丁里加两项：一条指向 模型网关 的模型路由（`dsh-llm-pi-ai`，OpenAI 兼容协议），一个 MCP 工具服务（`send_group_message`、`search_chat`）。系统提示词用环境变量 `DSH_SYSTEM_PROMPT` 给。

| 运行 | 内容 | 结果 |
| --- | --- | --- |
| r1 | 三批消息：闲聊；被 @ 问旧事；被 @ 要求算 2 的 100 次方并写文件 | 第一批不接话；第二批先查后答，答对；第三批用 shell 算出并写入 `pow.txt`，发群 |
| r1 续 | 关掉进程后重开，恢复同一会话，问「刚才那个数末三位」 | 答 376，正确。会话历史保留 |
| r2 | 沙箱设为「只可写工作区」，让它往工作区外写文件、访问本机服务 | 见第 3 节 |
| r3、r3b | 一个普通群友要求它原样执行一串命令 | 模型两次都拒绝了。这是模型的表现，不是框架的保证 |
| r3c | 系统提示词里指定管理员后，由管理员要求执行同一串自检命令 | 执行了，结果见第 3 节 |
| r4 | 工具改为脚本式调用，问一个要查两件事的问题 | 模型写 JavaScript，一段脚本里调两次查询再返回；最后用脚本发群 |

过程中见到的三个细节：

- 进程重启后，直接向已有的会话标识发消息会被拒绝（`session "…" already exists`），必须先调 `session/resume`。
- 发完消息后模型还会再走一步才结束（多一次调用，输出 5 个 token）。文章的做法是「发完就结束本轮」，dsh 的极简档里没有这个，需要自己加。
- r1 里有一次模型返回空内容，框架自动重试后正常。

## 3. 沙箱实测（Linux，bubblewrap）

把 `sandbox-policy` 的模式从极简档默认的「完全放开」改成「只可写工作区」后，在 shell 里跑自检：

| 项目 | 结果 |
| --- | --- |
| 写工作区内的文件 | 成功，宿主机可见 |
| 写家目录 | 被拒，「只读文件系统」 |
| 写 `/tmp` 或工作区外的路径 | 命令返回成功，但宿主机上没有这个文件。沙箱里的 `/tmp` 是另一块，写进去的东西不落到宿主机 |
| shell 环境里有没有模型密钥 | 没有（启动 dsh 时环境里有，shell 里查不到） |
| 读工作区外的内容 | **能读**。列得出家目录（21 项）和 `~/.dsh`（28 项） |
| 访问本机网络服务 | **能**。访问本机 8090 端口得到 HTTP 400，说明连得上 |
| 系统调用过滤 | 未开启 |

文档里的原话大意：这套沙箱只约束文件操作，不限制网络、进程和凭据；需要隔离环境的部署，应当把 shell 和文件能力换成容器、微型虚拟机或远程执行器。随包没有看到现成的容器后端。

Windows 上自带的后端是「访问控制列表 + 受限令牌」，文档标为「部分强制」。**未在 Windows 上试过。**

## 4. 和文章的做法逐项对照

| 文章的做法 | dsh | 依据 |
| --- | --- | --- |
| 外部程序驱动一个长期会话 | 有。排队发消息、收事件流、恢复会话、等待空闲 | 实跑 |
| 自定义工具（发消息、查记录） | 有。经 MCP 接入，或写成 dsh 插件 | MCP 实跑；插件只读文档 |
| shell 和工作区 | 有。极简档是常驻 bash（Windows 上是 PowerShell） | 实跑 |
| 脚本式工具调用 | 有。`tools.mode: ptc`，模型只看到 `run_code`，脚本里调其他工具，可并行（默认上限 10） | 实跑（串行）；并行未验证 |
| 子会话 | 有。`subagent` 工具，另有工作流脚本一次派多个 | 只读文档 |
| 上下文压缩 | 有。接近上限时把最旧的历史压成摘要，保留近期原文 | 只读文档 |
| 前缀只追加、缓存命中高 | 系统提示词分段拼接，动态内容走单独的「运行时上下文」。**命中率未验证**：模型网关 这条路没有返回缓存命中数 | 文档；事件里无此字段 |
| 独立容器、无密钥、只读根、资源上限、断网开关 | **没有**，要在外面套 | 第 3 节 |
| 小模型决定是否接话 | 没有，要自己写在驱动程序里 | - |
| 发完就结束、网络不明不重发 | 没有现成的，写在发送工具和驱动程序里 | - |
| 图片输入 | 协议支持在消息里带图片 | 只读文档 |

压缩这一项和我们的记忆设计有关：压缩出来的摘要就是文章警告的那种「加工过的记忆」。用 dsh 的话，要么调大窗口、让会话按天或按批重开，要么接受摘要但不把它当事实来源。这一点需要用户定。

## 5. 建议的结构（待用户定）

```
QQ 客户端（SnowLuma，OneBot v11）
      │ 反向 WS
宿主进程（我们写）：攒批、是否接话、发送、聊天记录库、记忆
      │ JSON-RPC（标准输入输出）        ▲ MCP：发消息 / 查记录 / 查印象
      ▼                                 │
容器（Linux；Windows 上经 WSL2）：dsh + 工作区，无 QQ 凭据，无聊天库
```

- 容器里只有 dsh、工作区和一把模型密钥。模型密钥也可以改由宿主进程代转，容器里一把都不放；这要多写一个转发，先不做也可以。
- 记忆系统（三个想法）全部在宿主进程一侧，以工具的形式给模型用。这样换框架（dsh 换 Pi）不影响记忆。
- 本机没有 docker 或 podman，只有 bubblewrap，所以容器这一层**本机没法试**，除非装一个容器运行时。

## 6. 和 AstrBot 相比

| | AstrBot | dsh |
| --- | --- | --- |
| QQ 接入 | 现成 | 自己写 |
| 群聊攒批、上下文、主动回复 | 现成（主动回复只有按概率） | 自己写，但也因此能照文章的规矩做 |
| shell 和工作区 | Windows 上只能禁执行或上第三方沙箱 | 现成；隔离靠外面套容器 |
| 脚本式工具调用 | 没有 | 有 |
| 子会话 | 有，实验性 | 有 |
| 提示词前缀由谁控制 | 框架和各插件，都能改 | 我们自己 |
| 版本 | 4.29.1 正式版 | 0.2.1-rc.4，候选版，接口可能变 |
