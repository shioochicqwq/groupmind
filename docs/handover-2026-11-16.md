## 0. 一句话现状

一个 QQ 小号以「群友」身份在一个群里**做影子测试**：每条消息都可能触发它回复，但它准备说的话不发进群，只记进 `shadow.jsonl`，并由小号私聊转发给主号看。机器人程序叫 **bothost**，跑在用户 Windows PC 的 WSL 里。每个群有一个 dsh 会话（通用 agent 内核），通过 MCP 拿到记忆、查证、看视频、认识人等工具。**所有改动都还没提交**（见第 7 节）。

## 1. 系统结构

```
                       用户 Windows PC                                         开发机（本机，可能迁移）
┌──────────────────────────────────────────────────────────────┐     ┌──────────────────────────────────┐
│ QQ 桌面客户端（小号，用户人工登录）                               │     │ Caddy :443（IP 证书）              │
│ SnowLuma v2.4.2 ──反向 WS──┐                                   │     │   └─ model-gateway :8318      │
│                           ▼        WSL 发行版 qqbot             │     │        ├─ /v1/chat/completions    │
│      ┌─────────────────────────────────────────────────┐     │     │        └─ /v1beta/models/*:generateContent
│      │ bothost（python -m bothost config.json）          │     │ ──► │            └─ 模型网关 :8317（Gemini 等）│
│      │  /ws  OneBot 服务端（收消息、发消息）               │     │     │                                  │
│      │  /mcp 工具服务（给 dsh 用）                        │     │     │ qqbot-data/（研究数据、库、人设）   │
│      │  每群一个 dsh 进程 ─ 插件 handoff.mjs、人设压缩     │     │     │ dsh 网页端「测试」预设（一对一）     │
│      │  data/memory.db  handoff.db  shadow.jsonl …      │     │     └──────────────────────────────────┘
│      └─────────────────────────────────────────────────┘     │
└──────────────────────────────────────────────────────────────┘          DeepSeek 官方 API（查证帮手、搜索）
```

一条群消息的路径：

1. SnowLuma 把 QQ 消息转成 OneBot v11 事件，推给 bothost 的 `/ws`。
2. `bothost/onebot.py` 把事件转成一行文字：时间、名字、正文，图片编号成【图片N】，卡片和视频写成链接，@ 写成真名。然后存进 `memory.db`。
3. 这个群的 worker 等一小会儿（`debounce_s`），把攒下的新消息合成一个回合，交给这个群的 dsh 会话。图片直接作为附件给主模型看，表情包另开调用看懂后再告诉会话。
4. 模型调用 `send_group_message` 说话；影子模式下只记录、转发，不发进群。
5. 遇到慢事（看视频、要开浏览器的网页），走**会话接力**（D-052）：旧会话留在后台把事做完，复制出的新会话接着聊群。旧会话收尾时用【回复】【摘要】格式交回结果，宿主决定是否引用原消息发出，再把摘要作为备注交给新会话。

## 5. 开发机迁移时要处理的

PC 上的机器人有两条依赖连回开发机：

1. **主模型和视频都走 `https://<GATEWAY_HOST>`。** 这个地址是开发机的 IP，证书也是签给这个 IP 的。迁移后：
   - 新机器上要有等价的网关。网关需要提供 `/v1/chat/completions`、`/v1/models`，以及 `POST /v1beta/models/<模型>:generateContent` 的原样透传，看视频要用后者。
   - 改 PC 上 `config.json` 的 `llm_base_url`、`video_base_url`，再重启 bothost。
   - 如果 `gateway.key` 也变了，替换 `secrets/gateway.key`。
   - **如果暂时没有网关**：在 `config.json` 里把主模型换回 DeepSeek（`model` 和 `llm_base_url` 改成 DeepSeek，key 换成 DeepSeek 的），并关掉 `llm_images`。这时图片和表情包都看不了，`stickers` 要另配一个能看图的模型才能开；视频也看不了。
2. **PC 的 ssh 是经开发机的隧道进来的**（`ssh pc` 走本机 2224 端口，由 PC 上的 `PcToDevSgTunnel` 任务建立）。迁移后要在 PC 上把这条隧道改指新机器，否则新机器连不上 PC。

开发机自己要搬走的：

- `qqbot-data/`（整个目录，含密钥文件和人设；体积大头在 `reconciled/`、`store/`、`vendor/`、`venv/`；`venv/` 可以在新机器上重建）。
- 本仓库的工作区。**改动都没提交**，迁移前要么提交，要么把整个目录原样带走。
- `~/.dsh/profiles/web/` 的测试预设和 `~/.dsh/bot/`（如果还要保留一对一测试会话的历史）。
- 网关 `~/.local/libexec/model-gateway/` 和 模型网关 的配置。

**PC 本身不受开发机迁移影响**：机器人在 PC 上自己跑，只是迁移那段时间网关不可用，模型调用会失败。

## 7. 没做完的事

### 7.1 已知缺陷（建议先修）

1. **工具调用超过 5 分钟一定失败。** dsh 调 MCP 工具走 HTTP，Node 自带的 `headersTimeout` 是 300 秒，配置里的「工具调用最长 1 小时」（`handoff_tool_timeout_s`）管不到这一层。
   - 2026-11-16 的一次查证跑了 5 分钟后返回 `fetch failed`，后台的查证帮手白跑了。
   - 后台会话里看一个处理时间超过 5 分钟的视频也会这样失败。
   - 建议的修法：工具自己在约 4 分半时先交差。看视频先返回「还没看完」，下次调用接着看（恢复 D-052 之前的做法）；查证在这个时间内必须给出结论。**等用户点头。**
2. **没交给后台的查证会挡住整个群。** 开着接力时，查证的预算被放宽到接近 1 小时。但只有读网页要升到浏览器档时才会交给后台，光搜索不读页的查证会一直占着群。实测有一个回合 563 秒，是两次长查证。建议：没交给后台时预算恢复 150 秒。**等用户定。**
3. **Gemini 主模型慢**：影子测试里 p50 18.1 秒、p95 90.1 秒，DeepSeek 是 2.4 秒和 4.4 秒。主模型是临时换成 Gemini 的（D-056），条件是「容易 503 就换回来」；目前没有 503，但慢。**要不要换回 DeepSeek，等用户定。**
