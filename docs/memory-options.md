## 0. 核心设计（用户说明）

- **保留原文是为了把原文喂给模型。**
- **上色既是索引，也是原文的分块方式。** 第一层颜色就是「微语境」，是一种语境划分，原文块不会很大；跨几周、上百条的内容属于第二层。
- **人物和时间是原文块绑定的元数据**，不是单独的检索通道，所以起点不需要多路融合。
- **主模型上下文很大（1M 级）**，而自有记忆系统本来就会让缓存命中率很低，所以起点不为缓存和长度优化；测试确实出现过大的情况时再处理。

检索流程起点（当前冻结版，D-028；向量配置见 D-029）：

```
机器人读到消息 → 主模型判断是否需要记忆 → 用最近几条原文检索
              → 颜色摘要、颜色原文块 × 关键词、向量，共四路，每路取前 5
              → 全局 RRF，按名次装入 1500 字 → 原文块带元数据注入当前消息前
```

最初的起点是「只用关键词检索颜色摘要，交给独立筛选模型（可返回空）」，现在两项都改为对照。
